# 로컬 메모리 시스템 v1

> Elizabeth Local-First Memory System v1 운영 문서입니다.

## 목적

Obsidian Markdown 트리를 로컬 SQLite에 인덱싱해서, 엘리자베스가 필요한 맥락만 빠르게 검색하고 압축해 사용할 수 있게 합니다.

## 구성

- Markdown 원본: `hermes저장소/엘리자베스/로컬 메모리 트리/`
- 시스템 파일: `_system/`
- 인덱서: `_system/memory_index.py`
- SQLite DB: `_system/memory.sqlite`
- 최신 컨텍스트 팩: `_system/latest-context-pack.md`
- 마지막 인덱싱 로그: `_system/last-index.log`

## 기능

- Markdown 파일을 제목/섹션 기준으로 청크화
- 청크당 기본 최대 약 3k 토큰 이하로 분할
- SQLite + FTS5 검색 인덱스 생성
- `profile`, `projects`, `decisions`, `daily`의 중요도 가중치 반영
- 민감 키워드 형태의 토큰/API 키/비밀번호는 인덱싱 전 간단 마스킹
- 질문에 맞는 압축 컨텍스트 팩 생성
- 매일 03:00 자동 재인덱싱

## 명령어

시스템 폴더로 이동:

```bash
cd '/home/hermes/Obsidian/Macidian/hermes저장소/엘리자베스/로컬 메모리 트리/_system'
```

인덱스 재생성:

```bash
python3 memory_index.py index
```

통계 확인:

```bash
python3 memory_index.py stats
```

검색:

```bash
python3 memory_index.py search '사용자 선호 실행 가능한 답변' --limit 5
```

컨텍스트 팩 생성:

```bash
python3 memory_index.py pack '사용자 선호 실행 가능한 답변' --token-budget 1000 --output latest-context-pack.md
```

테스트:

```bash
python3 -m pytest -q test_memory_index.py
```

## 자동화

Hermes cron job:

- 이름: `Elizabeth Local Memory Index`
- 일정: 매일 03:00
- 동작: `_system/memory_index.py index` 실행
- 성공 시 조용히 종료
- 로그: `_system/last-index.log`

## 운영 원칙

- 원문 전체 대화 저장보다 요약된 장기 기억을 우선한다.
- 민감 정보는 저장하지 않는다.
- 사용자가 Obsidian에서 Markdown을 직접 수정하면 다음 인덱싱 때 SQLite에 반영된다.
- `_system/` 아래 파일은 운영 파일이므로 일반 메모와 구분한다.

## 현재 v1 한계

- Gmail, Calendar, Notion 같은 외부 커넥터는 아직 붙이지 않았다.
- 압축은 로컬 규칙 기반이며, LLM 요약 압축은 아직 자동화하지 않았다.
- 검색은 SQLite FTS5 + 부분 문자열 보조 검색 기반이다.
